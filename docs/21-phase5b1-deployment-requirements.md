# 21 — Phase 5B.1 deployment requirements (API runtime)

No Dockerfile/compose exists in the repository; this is the contract any packaging must meet. Nothing here was deployed.

## 1. What must be in the deployed artifact

| Item | Location | Notes |
|---|---|---|
| Compiled app | `apps/api/dist/**` | from `pnpm --filter @meki/api build` |
| **Runtime assets** | `apps/api/dist/assets/**` (copied by the build) **or** `apps/api/assets/**` **or** `ASSETS_DIR` | 2 logos (`brand/MEKI_Primary_White.svg`, `MEKI_Icon_Gold.svg`), 4 fonts, 2 OFL texts. `nest build` deletes `dist/` — always use the package `build` script, not bare `nest build` |
| `node_modules` | production deps | includes `pdfkit`, `qrcode`, `sharp` (native binary for the target OS/arch), `exceljs`, `bidi-js` |
| Prisma client | generated by `prisma generate` (part of `build`) | and migrations folder for `migrate deploy` |

**Gate in CI/CD:** `pnpm --filter @meki/api build && pnpm --filter @meki/api verify:assets` must pass; the API itself **refuses to start** when assets or a configured font are missing (`TicketPdfService` startup self-test). `sharp` needs libvips from its prebuilt package — build/install on the same OS/arch (or `--platform` flags) as the runtime image.

## 2. Environment variables

Required in production (existing): `DATABASE_URL`, `NODE_ENV=production`, `WEB_URL`, `CORS_ORIGINS`, `API_PUBLIC_URL`, `TRUST_PROXY=<hops>`, `DONATION_TOKEN_SECRET` (≥32), payment variables only when a provider is approved.

Phase 5B/5B.1 (all optional unless stated):

| Variable | Default | Purpose |
|---|---|---|
| `EVENT_BOOKING_TOKEN_SECRET` | falls back to `DONATION_TOKEN_SECRET` | **set a dedicated ≥32-char secret** in production |
| `EVENT_BOOKING_RETURN_URL` | localhost | `{locale}`, `{slug}` placeholders — set to the real web URL |
| `EVENT_BOOKING_HOLD_MINUTES` | 60 | unpaid seat hold (only when capacity is configured) |
| `PRIVATE_STORAGE_DIR` | `./storage/private` | **persistent, non-public, backed-up volume**; relative paths depend on the working directory — use an absolute path |
| `ASSETS_DIR` | auto | only if assets live outside the app folder |
| `TICKET_PDF_UNICODE_FONT_PATH`, `…_BOLD_PATH`, `TICKET_PDF_LATIN_FONT_PATH`, `…_BOLD_PATH` | bundled Noto | override only with approved TTF/OTF; invalid path = startup failure |
| `MAIL_TRANSPORT` | `none` | `none` parks e-mails (nothing sent). `dev-file`/`memory` **forbidden** in staging/production. A real provider needs an adapter (not implemented) |
| `MAIL_DEV_OUTBOX_DIR` | `./storage/mail-outbox` | dev only |
| `GALA_JOBS_INTERVAL_SECONDS` | 30 | job poller; 0 disables (then call `POST /admin/events/:id/jobs/run` from a scheduler) |
| `GALA_JOB_MAX_ATTEMPTS` | 5 | |
| `GALA_EMAIL_ARABIC_APPROVED` | false | set true only after MEKI approves the Arabic copy |

Secrets and `.env*` files stay out of source control (`.gitignore` already covers `.env`, `.env.*`, `/storage/`, `/dist/`).

## 3. Checklist

1. Backup the production DB; `prisma migrate deploy` (applies `…phase5b_gala_booking` and `…phase5b1_booking_jobs`; additive); then `db:seed` (create-only; adds permissions, `EVENT_CHECKIN_STAFF`, Gala ticket config with **sales closed**).
2. Provision the private storage volume (and back it up with the DB — a lost PDF is regenerated per ticket with `POST …/tickets/:id/reissue` (rotates the QR), and `…/bookings/:id/regenerate-tickets` / the job runner cover tickets whose PDF was never produced).
3. Confirm `verify:assets` passes on the **built artifact**; start the API and look for `ticket PDF ready (assets: …)` in the log.
4. Run **one** API instance with the poller, or several instances — job claiming is lease-based and safe; rate-limit counters are per process until `RATE_LIMIT_STORE=redis` is wired (existing limitation).
5. Choose and wire an e-mail provider adapter before opening sales; until then confirmation mails are parked (`SKIPPED`) and tickets must be delivered from the booking page (`pdfReady`, token link).
6. Do **not** set a payment provider/mock in production; sales stay closed until MEKI + SDI approve (`salesEnabled`, needs `events.approve`).
7. Reverse proxy: forward only to `/api/*`; never expose the private storage directory; `TRUST_PROXY` = exact hop count.
8. Print one real ticket on the target paper and scan it with the door-staff phones before the event (not yet done).

## 4. Licensing of shipped assets

Fonts are **SIL Open Font License 1.1** (Noto Sans / Noto Sans Arabic; copyright The Noto Project Authors). Bundling with the application is permitted; keep the licence texts in `assets/fonts/` (they are included in `dist/assets`). The MEKI logos are copies of the existing approved brand files (`apps/web/public/brand`, byte-identical) and are not modified. Nothing proprietary from `client-resources/` is included.

## 5. Known production limitations

- No real e-mail delivery until a provider adapter exists.
- Poller is in-process (no external scheduler); if every instance is down, jobs wait (nothing is lost — they are rows).
- Private storage is local disk; `STORAGE_DRIVER=s3` throws “not configured” (the `PrivateStoragePort` is the only seam to implement).
- Only Latin and Arabic guest names can be printed (others are refused at booking with a clear error); ticket labels are English Latin-1.
- Arabic e-mail copy unapproved; Arabic event name/venue not supplied (tickets print the English configured labels).
- Event time/zone unconfirmed → calendar pending.
- Physical QR scanner/print compatibility unverified.
